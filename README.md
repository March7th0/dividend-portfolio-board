一个**单文件 HTML 应用**：为「长期股息型组合」的定投执行而做的作战台。
不是行情软件，不联网拉数据——它回答的是定投者每天真正要问的三个问题：

> **现在该买谁？买几手？剩下的钱等什么？**

> ⚠️ **免责声明**：本项目是作者个人投资纪律的工具化，不构成任何投资建议。
> 仓库中不含任何真实持仓、资金与流水数据（数据存于作者的云端资料库，不随代码分发）。

## 功能全景

| 模块 | 说明 |
|---|---|
| **估值看板** | 每只标的一张卡：安全边际仪表盘、档位标签、持仓盈亏、技术面扫描提醒 |
| **决策清单** | 按档位直接给动作：加倍定投 / 正常定投 / 减半定投 / 暂停买入，排除项不产生指令 |
| **建仓顺序卡** | 三桶规则（现在可买 → 等回落 → 不建仓），同层按安全边际深→浅排序 |
| **资金池 V2** | 本金/月度增量按标的建「专项池」，买入从池扣款，卖出回流待分配池，全程守恒可审计 |
| **分配引擎** | 先切层（按阶段比例）→ 层内按「目标仓位缺口」加权 → 取整到百元；方案优先、缺口兜底 |
| **阶段系统** | 核心层阶段 → 卫星层阶段 → 完整持仓阶段，进度驱动自动切换，可手动锁定 |
| **多档案隔离** | 每个档案独立的资金池/持仓/流水；物理层面互不触碰（状态表独立记录） |
| **关注层（多人协作）** | 个人关注 ∪ 公共池 = 「关注中」；支持「谁在关注」徽标、软删留痕、近实时同步 |
| **操作流水** | 每一笔分配/买入/卖出可撤销，撤销是真回滚不是补偿 |

## 策略框架（设计公开）

- **核心/卫星两层**：核心层压舱石（水电、银行），卫星层弹性进攻（能源、家电），目标仓位表驱动；
- **四档价位纪律**：每只标的维护「加倍买入价 / 正常定投上限 / 减仓起始价」，价格决定档位，档位决定动作；
- **三阶段推进**：核心先行（92.5/7.5 拆层）→ 卫星补足（20/80）→ 完整持仓再平衡，靠「手数进度」自动切换；
- **整手约束显式建模**：目标手数、已建、缺口全部按「一手股数 × 现价」实算，不做理论化的分数仓位。

> 以上是**设计**，不是业绩展示。每只标的的估值锚（内在价值/区间）由使用者自行维护。

## 技术形态

- **单文件交付**：`portfolio-workbench.html`（约 420KB），无构建、无依赖、离线可用；
- **数据层**：WorkBuddy 资料库 SDK（`window.__SMART_PAGE__.database`），带 localStorage 缓存、
  离线降级、SDK 迟到低频重连、自写回声抑制、防抖写库与分页续拉；
- **兼容性**：ES5 语法，平台 iframe 与现代浏览器均可运行；深/浅色主题；
- **测试**：**21 个 jsdom 套件 / 916 项断言**，全链路走真实 DOM 事件（见 `tests/`）。

## 跑测试

```bash
# 需要 node ≥ 18 与 jsdom（建议装在全局 node_modules，用 NODE_PATH 提供）
$env:NODE_PATH = "C:/Users/<you>/node_modules"   # Windows PowerShell
node tests/run_all.js          # 全部套件,汇总 PASS/FAIL,任一失败退出码 1
node tests/run_all.js poolv2   # 子串过滤
```

runner 为**进程内串行执行**（不 spawn 子进程——部分安全软件会拦截 node 嵌套 spawn 导致 EBUSY）。

## 数据与隐私

  私有环境；测试夹具全部为合成数据；
- 若你想在自己的 WorkBuddy 里使用，需要一个「页面 + 两张资料库」的宿主环境（估值表 + 状态表）。
